자연어 질의형 온톨로지 스마트공장 기술 개요서

2026-09-22 · 텔롬엑스(TelomX)

1. 기술 정의

기술명: 자연어 질의형 온톨로지 스마트공장 플랫폼 (Onto-Ask MES)

현장 작업자와 관리자가 평소 말투로 질문하면, 공장의 모든 데이터를 연결한 의미모델(온톨로지)에서 근거가 있는 답을 찾아 보여주는 MES 기술이다. 수주·품목·BOM·작업지시·로트·출하를 하나의 지식그래프로 묶고, 자연어 질문을 미리 검증된 질의로 바꿔 실행한다.

  • 공급기업: 텔롬엑스(TelomX)
  • 적용 대상: 다품종 소량생산 제조기업(조달 납품·가구·식품 제조 MES에 적용함)
  • 핵심 원칙: AI는 질문을 해석만 하고, 답은 항상 실제 데이터에서 나온다

2. 해결하는 문제

소기업 MES는 데이터를 쌓기는 하지만, 화면 여러 개를 옮겨 다니며 맞춰 봐야 답이 나온다. 실제 고객사 3곳의 MES를 실측해 확인한 문제는 다음과 같다.

문제현장에서 실제로 확인한 사례
같은 대상이 여러 벌 존재품목 마스터 2개(687행 + 661행)가 문자열 메모로만 이어짐, 거래처 마스터 2개(합계 28,056행)
연결이 화면 속에만 있음"이 자재가 늦으면 어느 수주가 밀리나"를 답하려면 자재 → BOM → 작업지시 → 수주 → 납품처를 사람이 차례로 조회
문서와 실물의 불일치출하 문서 합계와 실제 출고 원장이 다름(예: 문서 21 / 원장 20)
검색이 정확한 이름을 요구품목코드·거래처명을 정확히 알아야 찾음, 현장 작업자는 평소 부르는 이름으로 물음

정해진 화면만 늘리는 방식으로는 새 질문이 생길 때마다 개발이 필요하다. 반대로 생성형 AI에 DB를 직접 맡기면, 틀린 조인이나 지어낸 수치가 생산·출하 판단에 섞일 위험이 있다.

3. 기술 구성

기존 MES를 고치지 않고, 그 위에 온톨로지 계층과 자연어 질의 계층을 얹는 3계층 구조다. 온톨로지는 읽기 전용 복사본이고, 데이터의 원본은 항상 MES DB다.

4. 작동 방식

질문 하나가 답이 되기까지 4단계를 거친다. AI가 판단하는 것은 1단계뿐이고, 나머지는 검증된 질의와 실제 데이터가 처리한다.

  1. 해석: 질문을 의도(영향분석·재고·출하 등)와 조건(품목·기간·거래처)으로 나눈다. 규칙 파서가 먼저 처리하고, 의도를 못 찾은 질문만 LLM이 보강한다.
  2. 매핑: 의도에 맞는 검증된 질의를 고르고 조건을 파라미터로 넣는다.
  3. 추적: 지식그래프에서 관계를 따라가며 답을 찾는다(예: 자재 → BOM → 제품 → 수주 → 납품처). 실측 응답 약 10ms.
  4. 제시: 답과 함께 "어떻게 해석했는지"를 화면에 공개한다. 후보가 여럿이면 AI가 고르지 않고 사람에게 선택을 맡긴다.
질문 예시답이 나오는 경로현황
"이 자재 입고가 늦으면 어느 수주가 밀려?"자재 → BOM → 제품 → 수주 → 납기·수요기관영향분석 화면으로 운영 중
"이 수주 아직 몇 개 남았어?"수주 → 출하라인 → 실제 출고 원장운영 중(SQL 집계와 23건 전부 일치)
"유통기한 30일 남은 재고 보여줘"규칙 파서 → 재고 질의식품 MES에서 운영 중
"안전재고 밑으로 떨어진 품목은?"규칙 파서 → 품목 단위 재고 비교식품 MES에서 운영 중
"OO유치원 납품할 거래명세서 출력해줘"LLM이 거래처명만 추출 → 배송 건 조회 → 후보 선택구현 완료, 실운영 검증 전
"문서랑 실제 출고가 다른 수주 있어?"자연어 → 그래프 직접 질의개발 목표(검산기는 매일 실행 중)

5. 차별성

온톨로지가 답의 정확성을, 자연어가 쓰기 쉬움을 맡는다. 두 가지를 함께 갖춘 것이 기존 방식과 다른 점이다.

비교 항목기존 MES 검색LLM 단독 (Text-to-SQL)Onto-Ask MES
질문 방식화면별 검색창, 정확한 코드 필요자연어자연어
여러 단계 연결 추적화면을 옮겨 다니며 사람이 판단조인 오류 위험그래프 관계를 따라 한 번에
답의 근거화면에 보이는 것만설명이 어렵고 수치를 지어낼 수 있음해석 조건과 추적 경로를 공개
데이터 신뢰성점검 없음점검 없음불변식 매일 자동 검산
AI 비용·장애 의존해당 없음AI 없으면 작동 불가규칙 파서만으로도 작동
다른 고객사 확장화면 재개발고객사마다 프롬프트·검증 재작업공용 어휘 재사용, 변환기만 추가

재사용성은 실제로 확인했다. 조달 납품 업체용으로 만든 영향분석 질의가, 그래프 이름만 바꿔 가구 업체와 식품 업체에서 수정 없이 돌았다.

6. 적용 실적

업종이 다른 제조기업 3곳의 운영 MES에 적용했고, 지식그래프 약 28.6만 건이 매시간 자동으로 갱신된다(2026년 9월 기준).

적용처업종연결관계(트리플)자동 검산 항목주요 성과
A사조달 납품 칸막이 제조약 1.8만25자재 영향분석 화면 운영, 발주기관과 실제 납품처(수요기관) 구분
B사가구 제조약 18.0만34중복 마스터 통합: 거래처 28,056행 → 9,707개(65.4% 감소), 품목 661/661건 연결
C사발효식품 제조약 8.8만25자연어 검색 운영(질문 유형 8종), 출하 원장 23,002 = 그래프 23,002 일치

통합 과정에서 기존 MES로는 보이지 않던 문제도 드러났다.

  • B사에서 품목 마스터 두 개의 단가가 다른 품목 16건을 발견했다(통합 전에는 비교할 방법이 없었음).
  • A사에서 출하 문서와 실제 출고 원장이 다른 지점을 찾아, 잔량 판정을 원장 기준으로 바로잡았다.
  • 같은 사업자번호 아래 지점·부서가 섞인 거래처를 구분해, 납기 연락 대상이 잘못 지정되는 것을 막았다.

7. 기대효과와 향후 계획

도입기업은 화면을 배우지 않고도 말로 물어 공장 데이터를 쓸 수 있고, 공급기업은 고객사가 늘어도 같은 어휘와 질의를 재사용한다.

성과지표측정 방법
자재 지연 영향 파악 시간영향받는 수주·납품처 목록을 얻기까지 걸리는 시간(도입 전후 비교)
데이터 정합성자동 검산 항목 통과율, 문서·원장 불일치 건수
중복 기준정보 비율통합 전후 품목·거래처 개체 수
자연어 질문 처리율전체 질문 중 의도를 해석해 답한 비율

목표치는 도입기업의 현재 값을 먼저 잰 뒤 정한다.

향후 개발 계획

  1. 자연어 질문을 지식그래프 질의에 직접 연결한다. 현재 자연어 검색은 DB 질의를, 영향분석은 화면 버튼을 쓴다.
  2. LLM 보강 해석을 실운영에서 검증하고 질문 유형을 늘린다.
  3. 영향분석 화면을 B사·C사로 확대한다. B사는 BOM 등록이 먼저 필요하다.
  4. 로트 단위 품질 추적과 공장 간 공통 자재 연결로 범위를 넓힌다.
  • 확인 필요: 적용처 실명 공개 여부(현재 A·B·C사로 익명 처리)
  • 확인 필요: 영문 기술명 Onto-Ask의 상표 중복 여부(KIPRIS)
