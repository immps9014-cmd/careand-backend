02계층별 역할

위 계층은 바로 아래 계층만 부른다. 건너뛰는 호출은 두 가지뿐이다. MES 웹앱이 DB에 직접 쓰는 것, 검산기가 원장을 직접 읽는 것.

계층구성 요소맡은 일구현 · 위치
L5 클라이언트 현장 작업자와 관리자는 MES 화면을 쓴다. 사내 사용자는 claude.ai·Claude Desktop에서 커넥터로, 운영자는 서버 안의 Claude Code에서 같은 MCP 서버를 쓴다. 브라우저 · 현장앱(/m) · claude.ai 커넥터 · Claude Code(stdio)
L4 MES 웹앱 업무 화면과 모든 쓰기를 처리한다. hisense에는 온톨로지를 쓰는 자재 영향분석 화면이 있다. 자연어 검색은 질문을 조건으로 해석한 뒤 MES DB를 조회한다(그래프는 쓰지 않음). PHP 8.1 · CodeIgniter 3.1.13 · 사이트별 저장소
L4 MCP 서버 tx-ontology LLM이 부를 수 있는 도구 10개와 참고 리소스 4종을 제공한다. 결과 맨 앞에 데이터 기준 시각(freshness)을 붙이고, 호출마다 질문 원문과 처리 결과를 기록한다. hisense/scripts/ontology/mcp/ · core.php 하나에 도구 정의, 전송은 stdio·HTTP 두 갈래
L3 검증된 질의 목록 미리 작성하고 DB와 대조해 검산한 SPARQL만 실행한다. LLM과 MCP 서버는 질의를 만들지 않고 이름으로 고른다. 새 질의는 crosscheck에 DB 대조를 추가해 통과한 뒤에만 도구로 노출한다. application/libraries/Ontology.php · QUERIES 28개
L3 검산기 check.php는 개체 수·필수 연결·구조 불변식을, crosscheck.php는 도구가 쓰는 질의 결과를 원천 테이블과 한 건씩 비교한다. 그래프와 원장이 어긋나면 적발한다. 사이트별 check.php · mcp/crosscheck.php → out/crosscheck.json
L2 온톨로지 엔진 공용 제조 어휘(mes-core.ttl)와 사이트별 그래프를 보관하고, 관계를 따라가는 질의를 실행한다. 사이트는 이름 있는 그래프로 분리한다. Apache Jena Fuseki 6.1 · 데이터셋 tx-mes · localhost:3030
L1 ETL 변환기 사이트마다 다른 테이블 구조를 공용 어휘로 바꾼다. 중복 마스터는 병합하고 근거를 남긴다. 그래프는 PUT 한 번으로 통째 교체해서, 깨진 입력은 거부되고 기존 그래프가 남는다. etl_hisense.php · etl_infurs.php · etl_naturefood.php · load.sh
L0 MES 원장 모든 데이터의 원본(SSOT)이다. 잔량·출고처럼 판정이 걸린 수치는 출하 문서가 아니라 재고 원장 기준으로 적재한다. MariaDB · 사이트별 DB

03LLM의 위치

LLM은 두 군데에서 쓰지만 하는 일은 같다. 질문을 해석하고 어떤 도구·질의를 쓸지 고르는 것까지다. 수치는 항상 질의 결과에서 나온다.

MCP 경로 (외부 LLM)MES 내장 자연어 검색
LLM 위치사용자 쪽 Claude (claude.ai · Desktop · Code)MES 서버가 Claude API 호출 (Haiku 4.5)
LLM의 일도구 선택, 인자 채우기, 결과를 사람 말로 설명질문에서 의도·조건(품목·기간·거래처) 추출
데이터 원천온톨로지 그래프 (매시 스냅샷)MES DB (실시간)
AI 없이—규칙 파서만으로 작동 (naturefood 질문 8종)
비용 부담사용자의 Claude 구독, MES 서버에 API 키 불필요MES 서버 API 크레딧 (현재 부족으로 실운영 미검증)
못 하는 것쓰기 · 임의 SPARQL · 후보 중 임의 선택쓰기 · 임의 SQL (조건만 넘기고 질의는 고정)

두 경로 모두 "AI는 해석하고, 답은 데이터가 낸다"는 원칙을 따른다. 생성형 AI가 SQL이나 SPARQL을 직접 만들면 틀린 조인이나 지어낸 수치가 생산·출하 판단에 섞인다. 그래서 질의문은 사람이 쓰고 검산한 것만 남겼다.

04질문 한 건의 경로

2026-09-23 14:41 claude.ai 커넥터로 들어온 실제 질문 "hisense 미출고 수주 잔량 보여줘"를 따라간다.

  1. 도구 선택. claude.ai의 Claude가 질문을 읽고 order_remaining(site=hisense)를 고른다. 질문 원문은 question 인자로 함께 보낸다. LLM이 판단하는 단계는 여기뿐
  2. 진입. Anthropic 서버가 https://telomx.aiclaude.kr/mcp/<토큰>로 POST한다. Apache는 로그에 경로 대신 /mcp[path-hidden]만 남긴다.
  3. 인증과 기록. MCP 프로세스가 토큰을 sha256으로 대조하고 분당 호출 한도를 확인한다. 호출이 끝나면 질문·도구·결과 구분(answered / empty / ambiguous / error)을 한 줄로 기록한다.
  4. 질의 선택. core.php가 도구에 묶인 질의 이름 all_line_qty를 호출한다. 사이트는 그래프 이름으로 바꿔 넣는다.
  5. 그래프 조회. Fuseki가 수주라인 → 출하라인 → 원장 출고수량을 따라가 합산한다. 22ms, 잔량 남은 라인 0건이었다.
  6. 답. 결과 맨 앞에 데이터 기준 시각이 붙어 돌아간다. 150분이 넘으면 stale=true가 되고, Claude는 최신이 아니라고 알려야 한다. 이 답은 검산기로 확인했다. 수주 2건·23라인에 주문 183개, 원장 출고 183개로 모두 나갔다.

05데이터 갱신 주기

그래프는 실시간이 아니라 매시간 찍는 스냅샷이다. 사이트마다 분을 달리해, 메모리 3.6GB 서버에서 적재가 겹치지 않게 했다.

적재 한 번은 MES DB 읽기 → Turtle 생성 → HTTP PUT으로 그래프 통째 교체다. Fuseki는 파싱과 저장을 한 트랜잭션으로 처리한다. 그래서 변환 결과가 깨지면 400으로 거부되고 직전 그래프가 그대로 남는다. 적재 결과는 out/status.json에 남고, 화면의 "데이터 기준" 칩과 MCP의 freshness가 이 값을 읽는다.

07설계 원칙

계층 경계를 지키는 규칙이다. 바꾸려면 근거가 필요하다.

MES DB가 원본이다

온톨로지는 읽기 전용 투영이다. 쓰기(Action)는 기존 MES 엔드포인트로만 한다.

그래프에서 고치면 MES 불변식(재고 차감, 3경로 출하 이중차감 방지)을 우회한다.

질의는 사람이 쓰고 검산한다

LLM은 질의 이름을 고를 뿐이다. 새 질의는 DB 대조 검산을 통과해야 도구로 나간다.

검산이 실제로 잡은 결함이 있다. 출하를 수주로 센 질의, 번호 없는 옛 출하 10건 누락.

수치는 원장 기준이다

출고·잔량은 출하 문서가 아니라 재고 원장 수량(tx:shippedQty)으로 계산한다.

여러 출하 경로가 겹치면 문서 합계가 주문수량을 넘는다(문서 21 / 원장 20).

스냅샷임을 늘 밝힌다

화면과 MCP 응답에 데이터 기준 시각을 붙이고, 150분이 넘으면 경고한다.

시각이 안 보이면 한 시간 전 수치를 지금 수치로 읽는다.

고르지 않고 묻는다

이름 검색 후보가 여럿이면 LLM이 고르지 않고 사람에게 되묻는다.

같은 사업자번호 아래 지점·부서가 섞인 거래처가 실제로 있다.

개인정보는 내보내지 않는다

거래처 담당자 이름·전화·이메일은 도구 응답에서 뺀다. crosscheck가 누출을 매일 점검한다.

infurs 그래프에는 이 값들이 적재돼 있어, 질의 단계에서 고르지 않는 방식으로 막았다.

ID는 업무키로 만든다

IRI는 /id/{site}/{Class}/{업무키}로 만든다. DB PK 대신 수주번호·품목코드·로트번호를 쓴다.

item_id가 마스터 PK와 주문라인 PK를 오가는 이중 공간 문제를 구조적으로 막는다.

한 번 정의, 두 전송

도구는 core.php 한 곳에서 정의하고, stdio와 HTTP는 전송만 맡는다.

로컬과 원격의 도구가 어긋나지 않는다. 수정 후 systemctl restart tx-mcp-http.
