3루프 A · 적재

세 사이트 모두 같은 다섯 단계를 거칩니다. 스키마 mes-core.ttl은 hisense 레포에 한 벌만 두고 나머지 사이트가 그 파일을 읽습니다.

  1. flock으로 겹침 방지이전 실행이 안 끝났으면 건너뛴다. 사이트별로 :25 hisense, :40 naturefood, :55 infurs에 돌려 Fuseki 부하를 나눈다.
  2. ETL: DB를 Turtle로 투영etl_{site}.php. IRI는 mes.telomx.kr/id/{site}/{Class}/{업무키}. 업무키를 써서 item_id 이중공간을 구조적으로 없앤다. 개인정보·센서 시계열·Kitchen Sink 컬럼은 싣지 않는다.
  3. load.sh: 그래프 통째로 PUT파싱과 저장이 한 트랜잭션이라 깨진 입력은 400으로 거부되고 기존 그래프가 남는다. 그래서 별도 riot --validate를 쓰지 않는다(컨테이너 메모리 스래싱 원인이었다).
  4. check.php: 불변식 점검hisense 29 · infurs 36 · naturefood 26항목. "원장 실출고 = 그래프 출하수량", "스키마에 없는 술어 = 0", "이름이 같은 Partner = 0"처럼 연결의 양쪽을 센다.
  5. status.json과 한 줄 로그data_at·트리플 수·경고 수. MCP 응답의 freshness와 화면의 "데이터 기준" 칩이 이 파일을 읽는다. 150분이 지나면 stale.

5루프 C · 질의

질문 하나가 처리되는 순서입니다. 1~2와 6은 서버 지침(instructions)과 pitfalls:// 리소스가 Claude에게 요구하는 행동이고, 3~5는 서버가 강제합니다.

  1. 사이트 함정부터 읽기해석 전에 pitfalls://{site}와 common. 잔량은 원장 기준, 발주기관과 수요기관 구분, 다단 BOM 소요량은 추정하지 않기.
  2. 이름을 객체로 바꾸기resolve_entity. 후보가 둘 이상이면 고르지 않고 사람에게 묻는다(infurs는 "개별화물"만 14곳).
  3. 게이트 통과Apache /mcp → Bearer 또는 경로 토큰(sha256만 저장) · Origin 허용목록 · 토큰당 분당 120회. 경로 토큰은 로그에 남지 않게 가린다.
  4. 이름으로 질의 실행core.php → Ontology::QUERIES. 서버 안에 SPARQL 문자열이 없다. 타임아웃 5초, 200행 상한.
  5. 응답과 기록맨 앞에 freshness{data_at, stale}. question 인자의 원문을 호출 로그에 남겨 자연어 처리율 KPI 분모로 쓴다.
  6. 답하기기준 시각을 함께 말하고, stale이면 최신이 아니라고 밝힌다. 어떤 도구로도 답이 안 되면 log_unanswered를 한 번 부른다.

6루프 D · 변경

새 질문 유형을 받게 하거나 스키마를 바꿀 때의 순서입니다. 순서를 건너뛰면 검산 없는 질의가 Claude에게 나갑니다.

  1. 질의 추가hisense libraries/Ontology.php의 QUERIES에 이름을 붙여 넣는다. 수주·출하 겸용 관계는 클래스를 못 박고, 번호·라벨 같은 표시 속성은 OPTIONAL로 둔다.
  2. DB 대조 추가mcp/crosscheck.php에 같은 질의 결과를 원천 테이블과 맞추는 항목을 넣고 통과시킨다.
  3. 도구로 노출mcp/core.php에 도구 정의와 핸들러. 사이트별 차이는 pitfalls/{site}.md에 적는다.
  4. selftestmcp/selftest.php 59항목. 서버를 실제 프로세스로 띄워 확인하며, KPI 로그는 임시 파일로 돌려 실데이터를 오염시키지 않는다.
  5. 배포systemctl restart tx-mcp-http. stdio 쪽은 다음 세션부터 반영된다.
  6. 문서·PMSTX-ONT-MCP 개정 → PDF 재생성 → pms_push.js rev. 푸시는 운영자가 한다.

스키마를 바꿀 때는 hisense에서 load.sh --schema-only를 먼저 돌린다. 세 사이트의 check가 모두 "스키마에 없는 술어 = 0"을 보므로, 코어에 없는 술어를 ETL에 먼저 넣으면 다음 적재에서 바로 실패한다.
